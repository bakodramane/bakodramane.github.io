# Portfolio editorial review checklist

The portfolio redesign deliberately avoids inventing professional photographs, job titles, dates, contact details, research identifiers or outcomes. Before merging, review:

- **Professional biography:** verify all qualification wording and add any approved roles, dates, awards and additional qualifications.
- **Profile portrait:** supply an appropriate photograph if desired; until then, a deliberately designed “DB” monogram is used.
- **Publications:** verify bibliographic records and URLs, distinguish author/co-author status from institutional guidelines, and add any missing DOIs.
- **Projects:** check contributions, links and institutional attribution. Include quantifiable impact only when supported by evidence.
- **Applications:** supply real screenshots or confirmed live demos when available; GitHub source links already appear.
- **Contact:** personal email is not currently disclosed. Add only by explicit author preference.
- **Scholarly identifiers:** add ORCID and Google Scholar only after validating account ownership and URLs.
- **Multilingual parity:** translate any newly added portfolio pages to both languages; do not expose TODO notes.
- **Search/discoverability:** recheck page titles and social share previews after rebranding. The original social PNG remains until a new approved raster asset is provided.
- **Custom domain:** not changed; site remains on the existing working GitHub Pages URL.
- **Accessibility/performance:** run Lighthouse/axe with a browser on representative pages after deploy; automated build and link checks are not substitutes for manual WCAG review.
- **Deployment:** merge the reviewed pull request to main only after CI and content review; do not change the weekly publication schedule or existing post permalinks.
